## Commands

### Development
- `pnpm install` — Install dependencies (use `pnpm` not `npm`, as the repo has `pnpm-lock.yaml`)
- `pnpm dev` — Start development server on `http://localhost:3000` with hot reload
- `pnpm lint` — Run ESLint with automatic fixes

### Build & Deployment
- `pnpm build` — Build for production to `dist/` directory
- `pnpm preview` — Preview production build locally
- `pnpm deploy` — Deploy to GitHub Pages (runs build first, publishes to `gh-pages` branch)

## Architecture

### Project Structure
```
src/
├── pages/           File-based routing (each .vue file becomes a route)
├── components/      Vue components (includes graphs/ subdirectory for charts)
├── layouts/         Page layouts (default.vue is the main layout)
├── stores/          Pinia stores for state management
├── composables/     Utility functions (useDirectus, useApexChart, etc.)
├── plugins/         Vue plugins initialization
├── router/          Router configuration
├── styles/          Global SCSS (settings.scss configures Vuetify theme)
├── assets/          Demo data (dummyData.json) and GeoJSON files
├── config/          Configuration files
└── main.js          App entry point
```

### Key Technologies
- **Vue Router:** File-based routing via `unplugin-vue-router` — page structure in `src/pages/` auto-generates routes
- **Layouts:** `vite-plugin-vue-layouts-next` — wraps pages in layouts, default layout in `src/layouts/default.vue`
- **Auto-Import:** `unplugin-auto-import` + `unplugin-vue-components` — components and utilities auto-imported (no explicit imports needed in most files)
- **State Management:** Pinia stores in `src/stores/`
- **UI Framework:** Vuetify 3 with custom SCSS in `src/styles/settings.scss`
- **Mapping:** Leaflet for interactive map (`LeafletMap.vue`)
- **Charts:** ApexCharts via `vue3-apexcharts` (registered in `main.js`)
- **Visualization:** Includes graph components for trends, distributions, heatmaps, etc.

### Auto-Import System
The `unplugin-auto-import` plugin generates `.eslintrc-auto-import.json` automatically. Key auto-imported items:
- Vue composables: `ref`, `computed`, `watch`, `onMounted`, etc.
- Pinia: `defineStore`, `storeToRefs`
- Vue Router: `useRouter`, `useRoute`, `navigate`, etc.

This means components typically don't need explicit imports for these functions.

## Environment Setup

### Required Environment Variables
Create a `.env` file in the project root (see `.env.example`):

```
DIRECTUS_URL=http://your-directus-instance.example.com
DIRECTUS_TOKEN=your_static_token
VITE_BASE_PATH=/SoilSight/         # For GitHub Pages deployment (default: /)
```

- `DIRECTUS_URL` and `DIRECTUS_TOKEN` are server-side only (used by the proxy, never exposed to the browser)
- `VITE_BASE_PATH` is used in `vite.config.mjs` to set the build base path for GitHub Pages

### Proxy Architecture
All Directus requests go through a server-side proxy at `/api/directus`:
- **Local dev:** Vite dev server proxy (configured in `vite.config.mjs`) forwards to `DIRECTUS_URL` with `DIRECTUS_TOKEN`
- **Vercel prod:** Serverless function `api/directus-proxy.js` does the same
- The proxy adds the Authorization header, so tokens are never in the client bundle

## Directus Integration

The app supports optional integration with Directus headless CMS:

1. **API Calls:** Use `useDirectus()` composable in `src/composables/useDirectus.js` to fetch data
2. **Proxy:** All requests route through `/api/directus` — the proxy adds auth via `DIRECTUS_TOKEN`
3. **Dev Proxy:** Vite dev server proxies `/api/directus/*` to `DIRECTUS_URL` with token added automatically

## Gotchas & Patterns

1. **Auto-Import Magic**
   - Components defined in `src/components/` don't need explicit imports in templates
   - Utility functions from composables are auto-imported — you can use `ref`, `useRouter`, etc. without `import`
   - This can be confusing when reading unfamiliar components; check `unplugin-auto-import` config in `vite.config.mjs` to understand what's available

2. **File-Based Routing**
   - Routes are generated automatically from `src/pages/` directory structure
   - Moving or renaming files in `src/pages/` changes routes immediately
   - Nested routes are created by nested directories (e.g., `src/pages/farm/[id].vue` becomes `/farm/:id`)

3. **Env Variables at Build Time**
   - `VITE_*` variables are embedded at build time, not runtime
   - Changing `.env` requires restarting dev server
   - Production builds use `VITE_BASE_PATH` to set the base URL; verify this matches deployment path

4. **Dev Proxy Authorization**
   - The proxy in `vite.config.mjs` adds the bearer token header automatically
   - If `DIRECTUS_TOKEN` is blank or missing, Directus API calls will fail with 401/403

5. **GitHub Pages Deployment**
   - `pnpm deploy` uses `gh-pages` package to push `dist/` to the `gh-pages` branch
   - Ensure `VITE_BASE_PATH` is set to `/SoilSight/` if deploying to `github.com/AkunoCode/SoilSight`
   - Default base path is `/` (for root domain or custom domain)

6. **Chart Components**
   - Graph components in `src/components/graphs/` extend `ApexChartBase.vue`
   - Data passed as props; charts are reactive to prop changes
   - Use `useApexChart.js` composable for shared chart utilities

7. **ESLint Auto-Import Config**
   - `.eslintrc-auto-import.json` is auto-generated by the build system
   - Do not manually edit; regenerate by running `pnpm dev` or `pnpm lint`
   - If ESLint complains about undefined variables, check this file was generated

8. **Mobile Warning**
   - `useMobileWarning.js` composable provides mobile detection
   - Vuetify is responsive; use Vuetify breakpoints for responsive layouts, not custom media queries

## Development Workflow

1. Run `pnpm install` to set up dependencies
2. Create `.env` with Directus settings or leave empty for demo data
3. Run `pnpm dev` to start the dev server
4. Edit files in `src/` — changes hot-reload automatically
5. Run `pnpm lint` to check and fix code style issues
6. Run `pnpm build` to create production build
7. Run `pnpm deploy` to push to GitHub Pages (requires git remote and permissions)

## Common Development Tasks

- **Add a new page:** Create a `.vue` file in `src/pages/` — routing is automatic
- **Add a new component:** Create a `.vue` file in `src/components/` — auto-imported in templates
- **Add a new chart:** Create a `.vue` file in `src/components/graphs/` extending `ApexChartBase.vue`
- **Fetch data from Directus:** Use `useDirectus()` composable; falls back to demo data if not configured
- **Access router:** Use `useRouter()` and `useRoute()` composables (auto-imported)
- **Manage global state:** Define a Pinia store in `src/stores/` and use `useStore()` in components
